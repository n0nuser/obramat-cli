# Review, 2026-10-19

An adversarial pass over the whole tree once every command existed and the tests were green: what
the code claims against what the site does, then fidelity, robustness, security and cost. H must be
fixed before a release, M should be, L is noted. Each fix has a regression test named here.

## Fixed

| id | sev | finding | fix | test |
|---|---|---|---|---|
| R1 | H | Two back-to-back `store stock --all` sweeps (about 30 requests in 10 s) got a DataDome 403 that was still in place 45 s and 15 min later. The CLI would keep knocking on every later command. | Sweeps space requests 1.5 s apart; any block starts a 10-minute local pause during which site commands fail at once with exit 5; `watch run` sits it out. | `cli.TestBlockStartsAPause` |
| R2 | H | `--store 99` (no such store) was trusted. The site renders an unknown code as no store, so its default web prices were reported as store 99's. | Pages rendered for a store carry its code in `data-store-id`; without it the command exits 2. | `api.TestUnknownStoreIsRefused` |
| R3 | H | The store cookie without a store name made listings drop most prices (5 of 22 cards). Found during discovery; the fixtures first captured were taken with that cookie. | Cookie always carries a name; store fixtures recaptured. | `api.TestStoreCookieCarriesName` |
| R4 | M | `captcha-delivery.com` appears in every page's CSP; reading it as a block would fail every command. | Block = 403 with `X-Datadome` or the captcha body, or 429. | `api.TestNormalPageIsNotABlock`, `api.TestBlockIsExit5` |
| R5 | M | `--in-stock --limit N` counted products before filtering, so it could stop short. | Filter each page, then count. | covered by the search loop; see R9 for the server-side filter |
| R6 | M | A stock card with a green badge and no number would read as unavailable. | Badge colour decides when there is no number. | `api.TestStockCardWithoutNumber` (synthetic card) |
| R7 | M | `config set watch.interval abc` was saved and failed at the next watch command. | Durations and store codes are checked at `set`. | `cli.TestConfigSetChecksValues` |
| R8 | M | Cobra's own argument errors (unknown command, wrong arg count, missing required flag) exited 1. | Mapped to exit 2. | `cmd/obramat.TestBinaryContract` |
| R10 | L | `store stock --all` silently left out stores it could not place on the map. | A notice names them. | |
| R11 | L | Listings for a numeric `--store` had no store name in the header. | Taken from the cards' stock line. | `api.TestListFetchesLazyCards` (store fields) |
| R9 | M | With a store set, search pages offer a server-side stock filter (`stockAndDeliveryFilters`: code `availability`, value `inStockInStore`), and `--in-stock` filtered client-side instead. | `--in-stock` sends the toggle as an ordinary facet (`filters={"availability":"inStockInStore"}`, the toggle's `name`/`value`); the client-side sweep stays as a net for cards the site still returns without a stock line. | `api.TestInStockFilterParam` |
| R16 | H | DataDome refused the address itself: a browser User-Agent over Go's own TLS was not enough once the site had scored it (403 challenge page for curl and the CLI alike). | Requests go out over a Chrome TLS hello (`utls`, `HelloChrome_Auto`), and a browser session can be imported (`auth login`) and replayed: its cookies, its user agent, its client hints. | `api.TestChromeTransportHandshake`, `api.TestClientSendsSessionAndAbsorbsRotation`, `cli.TestAuthLoginStatusLogout` |
| R15 | L | The live round trip of the `--in-stock` filter was unconfirmed: DataDome refused the address (403, 773-byte page) and no real session existed. | With an imported session the search answers 200 and the toggle is applied: `search?q=tablero osb&filters={"availability":"inStockInStore"}` with store 22 returned the 4 in-stock products (`number:4`, `availability.applied:true`), captured as a fixture. | `api.TestInStockListing`, `api.TestInStockFilterParam` |

Also verified, no change needed: the stock quantity without a store is never reported (the site's flag
is 1/0, `api.TestProductWithoutStore`); env and config stay out of unit files except the paths and
`OBRAMAT_STORE`; config and state are 0600 and written atomically; site text is stripped of control
characters before it reaches a terminal (`output.Clean` in every table and error); MCP refuses unknown
arguments and puts positionals after `--` (`mcp.TestArgvFlagsThenPositionals`); `mcp install` keeps
other servers, other keys and large integers (`mcp.TestInstallJSONKeepsOtherEntries`).
