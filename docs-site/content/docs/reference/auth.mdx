## `obramat auth`

Import, inspect or forget the browser session

Import, inspect or forget the browser session the cli replays.

obramat.es sits behind bot protection that answers scripts with a challenge
page. The cli gets through by replaying your own browser's cookies (and its
user agent) over a Chrome-like TLS handshake. No password is ever asked for,
and an account is not needed: a guest session with a store selected is
enough.

### `obramat auth harvest`

Read the session out of a real Chrome window

```bash
obramat auth harvest [flags]
```

Read the obramat.es session straight out of your real Chrome, instead of
exporting cookies by hand.

The trusted datadome cookie lives in your everyday profile, not in a fresh one,
so the command copies just that profile's cookie store and keyfile into a temp
profile (0700, deleted afterwards) and opens Chrome on it. Chrome 136 and up
ignores --remote-debugging-port on the default profile, which is why it is a
copy and not an attach. The window is headed so you can clear any check it
shows; the command waits up to --timeout for that.

The profile is --profile / OBRAMAT_CHROME_PROFILE when set, else the first of
the usual Chrome and Chromium locations that has cookies. Without one, or with
--browser-url, the behaviour changes:

  --browser-url URL   attach to a Chrome already listening on a devtools port
                      (env OBRAMAT_CHROME_URL, or the default
                      http://localhost:9222). Chrome 136+ only exposes that on
                      a profile started with it.
  no real profile     open a fresh window instead; it has no trusted cookie, so
                      a captcha may need clearing by hand.

The harvested cookies and the browser's own user agent are stored 0600 exactly
as `auth login` stores an export.

```bash
obramat auth harvest
obramat auth harvest --profile ~/.config/google-chrome --timeout 2m
obramat auth harvest --chrome /usr/bin/chromium
obramat auth harvest --browser-url http://127.0.0.1:9222
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--browser-url` | string | - | attach to this Chrome DevTools endpoint instead of launching (env OBRAMAT_CHROME_URL; default: probe http://localhost:9222) |
| `--chrome` | string | - | Chrome or Chromium binary (env OBRAMAT_CHROME) |
| `--profile` | string | - | real Chrome profile to copy the cookies from (env OBRAMAT_CHROME_PROFILE; default: the usual Chrome/Chromium locations) |
| `--timeout` | duration | `5m0s` | how long to wait for the challenge to clear |
| `--user-agent` | string | - | override the user agent (default: the browser's own) |

### `obramat auth login`

Import obramat.es cookies or a HAR from your browser

```bash
obramat auth login [flags]
```

Import obramat.es cookies or a HAR exported from your browser.

1. Open obramat.es in Chrome and choose your store.
2. Export the cookies with a cookie-export extension (JSON or cookies.txt),
   or save a HAR from DevTools > Network with "Allow to generate HAR with
   sensitive data" enabled.
3. Pass the file here.

Accepted: cookie JSON (array or \{"url","cookies"} wrapper), DevTools cookie
lists, Netscape cookies.txt, a Cookie: header, HAR 1.2. Only obramat.es
cookies are kept, so a whole-browser export is fine. A HAR also carries your
browser's user agent, which the cli then sends.

The session is stored 0600 under the config directory. For CI, point
OBRAMAT_COOKIEJAR at an export instead: it is read on each run and never
written to disk.

```bash
obramat auth login --cookies ~/Downloads/obramat-cookies.json
obramat auth login --har ~/Downloads/obramat.har --no-check
pbpaste | obramat auth login --cookies-stdin --cookies-format header
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--cookies` | string | - | cookie export file (JSON, cookies.txt or a Cookie: header) |
| `--cookies-format` | string | `auto` | auto, json, netscape, header or har |
| `--cookies-stdin` | bool | `false` | read the export from stdin |
| `--har` | string | - | HAR file saved from DevTools with sensitive data included |
| `--no-check` | bool | `false` | save without asking the storefront whether the session works |
| `--user-agent` | string | - | user agent of the browser the cookies came from (a HAR provides it) |

### `obramat auth logout`

Forget the stored browser session

```bash
obramat auth logout
```

Delete the stored session. Your browser session is not touched.

### `obramat auth status`

Show the session in use (cookie names only, never values)

```bash
obramat auth status [flags]
```

Show where the session comes from and what it carries. Values are never
printed. With --check it asks the storefront whether the session still works:
one request, and the answer the site gives a challenged session.

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--check` | bool | `false` | also ask the storefront whether the session works (one request) |
